Options for a production site

All three reuse the same DuckDB database and its dictionaries of names in nine languages.

Recommended

Static site: DuckDB → JSON → ECharts

  • What these mockups already are: one export script, plain pages, GitHub Pages hosting.
  • No server, no database to run; rebuild with each data release.
  • Next step: move the pages into Observable Framework for routing and data loaders if the site grows past ~10 pages.
Alternative

Evidence or Observable Framework

  • Pages written in Markdown + SQL against the database at build time.
  • Fast to add new tables and charts; Evidence ships treemap and Sankey components.
  • Less control over bespoke views such as the tax receipt.
Heavier

Fork Civio Presupuesto or Open Budget Sacramento

  • Mature citizen UX: search, programme pages, receipt, comparisons.
  • Requires remapping the Armenian functional and economic classifications.
  • Civio needs Django + Postgres hosting; Sacramento is static but has fewer views.

About the data in the mockups

Amounts come from the Council's budget decisions (approved budget, appendices 1–7) and the form Հ-9 execution reports (approved plan, revised plan and actual, cumulative by quarter). They are nominal AMD; the database stores thousand AMD, the mockups show million and billion.

The budget books land and property sales as negative spending under “Economic affairs n.e.c.”. Composition views show gross allocations; totals and trends use net figures as published. Internal transfers between the administrative and fund parts of the budget are left out.

Regenerate the data with python viz/export_data.py --db data/yerevan_budget.duckdb.
